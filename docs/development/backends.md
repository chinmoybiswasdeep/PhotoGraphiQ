# Adding a backend

Implement BaseBackend reset, prepare, entangle, displace, rotate, squeeze, beamsplitter, measure and get_state. Advertise only implemented capabilities and validate resources before allocation. Maintain labels through destructive measurements and requested output reordering. Use statistical covariance and hbar=2 interface units. Add independent analytical tests, native comparisons, unsupported-operation checks and memory guards. Mixed outputs do not imply mixed trajectory evolution. Register the backend in `photographiq.registry` with its representation, capabilities, approximations, required Python packages and native components, so that `describe_backend`, `available_backends` and `select_backend` report it correctly. Native engines subclass the validated Python backends and must be cross-checked against them (`tests/native`, `tests/cross_backend`).

See [numerical policy](../validation/numerical-policy.md), [API](../api/index.md) and the [feature matrix](../validation/feature-matrix.md).
