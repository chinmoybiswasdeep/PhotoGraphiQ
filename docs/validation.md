# Validation scope and limitations

The test suite is executable evidence, not a proof of correctness for every
possible input. Run `python -m pytest --cov=photographiq` to obtain current counts
and coverage. The checked local environment is recorded in
`paper/results/environment.json`; `requirements-lock.txt` freezes its dependencies.

| Suite | Evidence |
|---|---|
| unit | invalid graphs/states, parameters, causal errors, JSON security and label preservation |
| analytical | independent gate matrices, nullifiers, conditioning, statistics, CV-flow equations, compiler channels |
| protocols | teleportation and wire ensembles, adaptive agreement, symplectic decomposition |
| piquasso_reference | raw resources/gates, conditional general-dyne moments, target circuits, upstream sampler characterization |
| graphix_reference | graph connectivity, I/O, measurement order, domains and safe standardization |
| integration | Fock resources, conditional counting, explicit unsupported operations, diagram export |
| regression | optimization and displacement-frame equivalence |

Deterministic floating-point comparisons generally use 1e-10–1e-13 on modest
examples. Monte Carlo tests use fixed seeds and absolute tolerances appropriate
to their finite shot counts; they are statistical checks rather than precision
gate-fidelity claims. Piquasso and NumPy Gaussian backends share the exact
conditioning adapter. Agreement between them alone is therefore not independent
measurement validation: analytical Schur checks and independent measurement
statistics supply that evidence. The affine Wigner analyzer is a separate
implementation from conditional trajectories.

The pinned Piquasso Gaussian sampler currently passes its anticommutator
covariance to NumPy without the statistical factor of one half. A vacuum
heterodyne characterization test observes variance approximately 4 rather than
the physical variance 2 in hbar=2 coordinates. PhotoGraphiQ uses its own exact
sampler and conditioner; this behavior is documented rather than disguised by
test tolerances. Native detector-conditioned states are checked at native outcomes,
which tests state updates, not those outcomes' physical probability distribution.
The Gaussian Homodyne z parameter approximates an ideal quadrature using
diag(z^2,z^-2). No such finite-detector approximation is used by PhotoGraphiQ.

## Implemented scope versus remaining research

* Gaussian MBQC, affine gate compilation, total-order CV-flow certification and
  finite-squeezing analysis are implemented. A full optimal CV-flow/order finder
  is not. Binary gflow, Pauli flow and qubit Clifford preprocessing are not ported.
* The pure-Fock adapter supports resource experiments, photon counting and ideal
  adaptive homodyne. Noisy Fock homodyne is rejected. Gaussian photon counting is rejected because its conditional
  state is non-Gaussian. Mixed Fock preparation, GKP resources and non-Gaussian
  universal compilation remain future work.
* Norm monitoring detects many cutoff problems but is not a rigorous Fock error
  certificate. Convergence must be checked at increasing total-photon cutoffs.
* The Gaussian trajectory implementation uses dense covariance matrices, with
  physicality checks involving dense eigensolvers. It prioritizes validation over
  optimized large-resource scaling. Beam-splitter compilation is especially costly.
* General-dyne simulation is supported, but exact channel analysis currently only
  supports homodyne and affine feed-forward. Nonlinear adaptive mixtures generally
  require trajectory observables rather than a Gaussian fit.
* Generic mode mismatch, dephasing, experimental interferometer synthesis,
  differentiable batching, hardware execution and fault-tolerance studies are not
  implemented. Temporal and dual-rail graph labels alone do not model hardware.

## Build and manuscript evidence

The paper derives the convention choices, measurement updates, teleportation
channel, compiler and frame transformations. Data are generated by
`experiments/reproduce.py`; timing fields describe this machine only and are not
comparative performance claims. The manuscript uses the official Quantum class.
It is a draft with collective contributor metadata, to be finalized by the actual
authors; no acceptance, DOI, affiliation or experimental result is invented.


## Non-Gaussian extension validation

The additional suites `tests/fock`, `tests/non_gaussian`, `tests/cutoff` cover
multimode preparation/import, reduced mixed states, cat moments, Kerr/cubic gates,
independent dense test operators, ideal ladder factors, physical heralding,
conditional Hermite projection, seed/CDF agreement, injection wavefunction
integration, Wigner normalization/negativity, aligned metrics and cutoff scans.
Graphix compares only the injection causal skeleton. Native Piquasso programs
validate counting distributions and gate execution; native homodyne does not
provide a conditional-state reference, so that update has an independent
analytical test. Different finite-Fock Gaussian decompositions are compared with
cutoff-dependent tolerances; identical sequences agree at numerical precision.

`experiments/non_gaussian.py` writes measured convergence data, figures and local
timings. Norm conservation is not a convergence certificate. Runtime warnings in
validation artifacts expose deliberately tested truncation and boundary effects.


## Numerical test classes and error budgets

| Class | Examples | Assertion model |
|---|---|---|
| A: algebraic/deterministic | Kerr phases, ladder factors, dimensions, causal domains | Tight float64 absolute/relative error; exact integers/sets where appropriate |
| B: finite-cutoff | Cubic gates, native Gaussian decompositions, injection | Several cutoffs; retained norm and boundary diagnostics; independent high-cutoff accuracy targets |
| C: Monte Carlo | Photon counts, Gaussian detector samples | Fixed independent seeds; shot-count-scaled sampling uncertainty, not precision amplitude tolerances |
| D: quadrature | Fock homodyne inverse CDF, injection wavefunction integrals | Separate integration error estimates, interval refinement and Hilbert truncation error |

The original Linux injection density failure **did not execute quadrature**:
fixed-outcome conditioning contracts a Hermite vector, and its reference density
is analytical. At c=36 the density error was 2.0235e-5, just beyond the old
2e-5 threshold. The regression retains c=36 but verifies improvement at c=96
and a stricter 1e-6 absolute density target. Multiple (gamma,r,m) values also
must reach 1e-7 state infidelity against independently integrated wavefunctions.
Refining that oracle's integration tolerance and interval changes its normalized
vector by less than 1e-9, separately from the Fock budget.

For direct SUM versus Fourier-CZ, c=12,18,24,32,48 are retained, including both
original failed c=24/48 cases. Tests require decreasing asymptotic infidelity,
boundary population and norm loss. Original Linux and Windows runs both showed
more than 20-fold infidelity improvement from c=24 to c=48; the regression
requires only a tenfold improvement. This is an empirical acceptance criterion
for the stated parameter regime, **not** a proven universal convergence rate.
The c=12 diagnostic scan explicitly permits and reports underresolved norm loss;
production defaults continue rejecting excessive truncation.

Low-cutoff errors need not decrease at every step: the original density scan
increases between c=12 and c=18. Neither monotonicity nor norm conservation is
assumed to prove an infinite-dimensional limit. Identical native instruction
sequences retain direct vector comparisons; different realizations and physical
state comparisons use squared fidelity or phase-aligned vectors.

## Reproduction and CI provenance

Run `python experiments/validate_release.py --output .validation` with each
interpreter. It runs pytest, Ruff lint, Ruff formatting, mypy, build and numerical
evidence generation even when an earlier gate fails. The JSON records exact
installed packages, interpreter, platform, exit codes, Git HEAD and a normalized
source/test/configuration SHA-256. Logs and test XML are separate artifacts.

The workflow tests Python 3.11, 3.12, 3.13 and 3.14 with fail-fast disabled and
uploads per-version evidence. A workflow configuration is not a green run:
[the release report](release-hardening-report.md) identifies actual local and
remote outcomes. Local historical paper XML and the frozen v0.2 environment are
not substitutes for these per-version reports.
